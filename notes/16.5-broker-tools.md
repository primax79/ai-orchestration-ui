# 16.5 Broker MCP Tools — Implementation Notes

## Overview

Task 16.5 evolves the minimal broker spike from 16.1 into the v1 MCP broker over the `ai-orch` engine CLI.

Key architectural properties:
1. **Engine as Source of Truth:** The broker never mutates task files directly on disk. All reads and writes are routed through `ai-orch ... --json`.
2. **Broker Singleton & Write Ownership:** The broker acquires `broker.lock` in the configuration directory via `scripts/orchestration_broker_lock.py:acquire_broker_lock()`. Mutating CLI calls executed outside the broker fail with exit code 75 (`broker-owns-writes`). The broker runs all CLI children with `AI_ORCH_BROKER_CHILD=1`, allowing its operations to proceed.
3. **Explicit Workspace & Project Scoping:** Every project-level tool takes `workspace` (slug or uuid) and `project` (slug or uuid). Trees are resolved via `ai-orch workspace show` and `ai-orch projects list`, never inferred from the working directory.
4. **No Nulls Policy:** All responses are stripped recursively of `None`/`null` fields at the source before serialization.
5. **Paging & Size Cap:** Lists accept `cursor` and `limit` (default 50, max 200) and return `next_cursor` when more items exist. Responses exceeding 256 KiB are truncated with `truncated: true` and a continuation `next_cursor`.
6. **Deterministic Mutations:** Mutations accept `idempotency_key` (forwarded to `--idempotency-key`) and `expect_hash` (forwarded to `--expect-task-hash` for CAS verification). `preview: true` previews actions without mutation.

## Implemented §3b Tool Contract

| Tool | Arguments | Returns | Description |
|---|---|---|---|
| `whoami` | None | `ok, broker: {pid, version, started_at}, unread_mail` | Broker identity and status |
| `workspaces.list` | `cursor?, limit?` | `ok, items: [{uuid, slug, title, path, orchestrator, unread_mail}], next_cursor?, truncated?` | List registered workspaces with orchestrator status |
| `projects.list` | `workspace` | `ok, items: [{uuid, slug, path, kind}]` | List projects in workspace |
| `tasks.list` | `workspace, project, state?, kind?, label?, text?, cursor?, limit?` | `ok, items: [{id, short_title, title, state, priority, kind, size?, parent?, depends_on: [], hash}], next_cursor?, truncated?` | Compact task list with filtering and paging |
| `tasks.show` | `workspace, project, id` | `ok, task: {id, short_title, title, state, header: {}, goal, steps, verification, children: [], attachments: [], hash, path}` | Full task details |
| `tasks.next` | `workspace, project?, cursor?, limit?` | `ok, items: [...] (ready queue order)` | Tasks ready for execution |
| `tasks.graph` | `workspace, project` | `ok, nodes: [{id, short_title, state, column}], edges: [[from, to]], ready: []` | Dependency graph |
| `tasks.new` | `workspace, project, title, short, goal, category?, priority?, priority_reason?, kind?, parent?, idempotency_key?, expect_hash?, preview?` | `ok, id, hash, path` | Create a new task |
| `tasks.transition` | `workspace, project, id, to, note?, idempotency_key?, expect_hash?, preview?` | `ok, id, from, to, hash` | State machine transition |
| `tasks.set` | `workspace, project, id, field, value, idempotency_key?, expect_hash?, preview?` | `ok, id, field, value, hash` | Update field (`priority`, `size`, `deps`, `kind`, `labels`, `short`) |
| `questions.list` | `workspace, project?, status?, cursor?, limit?` | `ok, items: [{id, short_title, question, status, blocks: [], decider}]` | List blocking questions |
| `questions.ask` | `workspace, project, question, short, context, options, recommended?, blocks?, idempotency_key?, expect_hash?, preview?` | `ok, id, hash` | Create a blocking decision |
| `questions.answer` | `workspace, project, id, choice, text?, idempotency_key?, expect_hash?, preview?` | `ok, id, unblocked: []` | Answer a decision and unblock tasks |
| `inbox.add_note` | `workspace, project, title, body, kind?, idempotency_key?, expect_hash?, preview?` | `ok, id, path` | Add an inbox note |
| `orchestrator.status` | `workspace` | `ok, state, tool?, model?, generation?, queue_length, worker: {alive}, unread_mail` | Status of workspace orchestrator |

Compatibility aliases: `tasks_list`, `debug_sleep`, `debug.sleep`.

## Starting the Broker & Stdio Shim

### 1. Broker Server (HTTP Daemon)

The broker server can be launched directly:
```bash
python -m backend.broker serve
# Or specify host/port:
python -m backend.broker serve --host 127.0.0.1 --port 8782
```
On startup:
- Acquires `broker.lock` in `$AI_ORCHESTRATION_CONFIG` (or `~/.config/ai-orchestration`).
- Writes connection info to `broker.json` (`pid`, `port`, `started_at`, `token_file`).
- Serves `/mcp` over Streamable HTTP with `x-ai-orch-token` authentication.

### 2. Stdio Shim

The stdio shim connects standard MCP clients via stdin/stdout to the running broker (auto-launching the broker if not already running):
```bash
python -m backend.broker shim
```
