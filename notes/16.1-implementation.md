# 16.1 Implementation Notes: Minimal MCP Broker and Stdio Shim

## 1. Overview & Architecture

Task 16.1 implements the prototype MCP broker and stdio shim for `ai-orchestration-ui`, establishing the client integration spike required by spec §8 step 2.

### Components
1. **Broker Process (`backend/broker/server.py`, `python -m backend.broker serve`)**:
   - Single-instance lifecycle managed by `broker.lock` (`fcntl.flock(LOCK_EX | LOCK_NB)`) inside the config directory (`AI_ORCHESTRATION_CONFIG` or `~/.config/ai-orchestration`).
   - If another instance attempts to start, it terminates immediately with code 1 and writes `Broker is already running (locked by another process)` to `stderr`.
   - Writes `broker.json` containing `{pid, port, started_at, token_file}` atomically only after the lock is acquired.
   - Serves MCP over Streamable HTTP on `127.0.0.1` (random free port or user-provided `--port`), wrapping Starlette with `BrokerTokenAuthMiddleware` which enforces the `x-ai-orch-token` header (or `Authorization: Bearer <token>`).
   - Registers three tools:
     - `whoami`: returns JSON string with `broker_pid`, `version`, `config_dir`, and `bound_client` (also aliased for callers).
     - `tasks_list(project_path: str)`: validates that `project_path` exists, contains a `tasks/` directory, and contains `tasks/00-INDEX.md`; then runs `ai-orch tasks list --tasks-dir <project_path>/tasks --json` and returns the output. Refuses invalid paths.
     - `debug_sleep(seconds: int ≤ 120)`: sleeps for the specified duration to test long-call and timeout behavior.
   - Module-level hook `backend.broker.server.unread_notice`: when set, appends a one-line human-readable notice to the text content of tool results per spec §5.

2. **Stdio Shim (`backend/broker/shim.py`, `python backend/broker/shim.py`)**:
   - Communicates with MCP clients over `stdin`/`stdout` using JSON-RPC line framing.
   - Answers the `initialize` handshake immediately with static capabilities and server info, before the broker is running.
   - Manages broker lifecycle: checks `broker.json` and process liveness; if absent or stale, attempts to acquire `broker.launch.lock` (`fcntl.flock(LOCK_EX | LOCK_NB)`). The winning shim spawns `broker serve` detached (`start_new_session=True`), while other concurrent shims poll readiness with a 50 ms backoff.
   - Forwards JSON-RPC tool calls (`tools/list`, `tools/call`, `ping`) over Streamable HTTP to the broker with the authentication token.
   - Fault-tolerance: if the broker is terminated or crashes mid-session, the shim detects the connection failure, relaunches `broker serve` via the launch lock, and transparently retries the request once.

3. **Entry Points**:
   - CLI: `python -m backend.broker serve [--port PORT]`
   - Stdio shim: `python backend/broker/shim.py` or `python -m backend.broker shim`
   - Wrapper script: `bin/ai-orch-broker serve`

## 2. Starting the Broker and Shim

### Direct Broker Server
To start the standalone broker HTTP server:
```bash
./bin/ai-orch-broker serve
# Or via python:
.venv/bin/python -m backend.broker serve --port 8790
```

### Direct Stdio Shim
To launch the shim in an stdio session:
```bash
.venv/bin/python backend/broker/shim.py
# Or via python module:
.venv/bin/python -m backend.broker shim
```

## 4. Verification

All requirements were verified with automated unit tests in `backend/test_broker.py`:
- `test_broker_singleton`: Confirms that running a second `broker serve` fails with returncode 1 and logs that the broker is already running.
- `test_shim_initialize_answered_before_broker_up`: Verifies that `initialize` is answered immediately by the shim without waiting for broker process launch.
- `test_two_shims_concurrent_start_one_broker`: Starts two shims simultaneously; both execute calls against the single launched broker process.
- `test_tools_callable_through_shim`: Exercises `whoami`, `debug_sleep`, and `tasks_list` over raw JSON-RPC on `stdin`/`stdout`.
- `test_broker_killed_between_calls_relaunches`: Sends `SIGKILL` to the running broker; the subsequent call through the same shim triggers auto-relaunch and succeeds.
- `test_tasks_list_refuses_path_without_tasks`: Confirms non-existent paths, folders lacking `tasks/`, or missing `00-INDEX.md` return `isError: true`.
- `test_unread_notice_appears_in_text_content`: Validates that setting `broker_server.unread_notice` appends the notice to the tool output content text.

Running the full test suite:
```bash
.venv/bin/python -m pytest -q backend
# Result: 74 passed in 76.73s (no regressions, previous count: 67)
```

## 5. What Could Not Be Verified (Out of Scope for 16.1 Implementation Part)

1. **Interactive Client UI Testing**: Live verification inside the interactive CLI prompts of Claude Code, Kilo IDE extension, and Codex binaries using isolated temporary user configs (`--isolated`). This is part of the follow-up manual/client verification matrix in task 16.1.
2. **Non-Unix Platforms**: `fcntl.flock` is standard on macOS and Linux; Windows environments would require equivalent file-locking adaptations (e.g. `msvcrt.locking` or portalocker) if supported in future releases.
3. **Advanced Broker Tools & State Stores**: Mutations (CAS writes), SQLite registry, mailbox stores, and orchestrator turns belong to subsequent tasks (16.2–16.8).
